2. Identified Gaps
Critical Gaps
1. Rulebook Navigation is Fragmented
   * PDF viewer requires manual page navigation
   * Search results don't link back to PDF pages
   * No way to jump from questions directly to relevant rules (despite rule references being captured)
   * Rules are parsed but relationships between questions and rules are one-way only
2. Game Analytics Completely Missing
   * 56 games tracked but no analysis of referee performance, earnings trends, or patterns
   * No metrics like "earnings per game", "most frequent location", "average payment delay"
   * No filtering by location, referee role, or other patterns
   * Payment tracking is crude (Yes/No only)
3. Test-Game Disconnect
   * Testing is isolated; no connection to actual game scenarios
   * No way to note "I got this question wrong, and it came up in game X"
   * No way to review a game's relevance to test performance
4. Multi-User Readiness: Zero
   * All data is singleton (one referee's data per installation)
   * No user accounts, logins, or multi-user database design
   * No sharing of test sessions or game records
   * No collaborative features (e.g., comparing performance with other referees)
5. Data Export/Sharing Limitations
   * Games export to CSV works, but tests cannot be exported
   * No PDF generation for reports (e.g., "test report for certification")
   * No way to share progress with coaches or peers
6. Test Question References Underutilized
   * Questions have rule references extracted but not displayed during tests
   * Answer explanations are shown but rule links are not interactive
   * No way to jump from test feedback to the relevant rule
7. Payment Workflow Incomplete
   * Payment date is optional and freeform
   * No alerts for overdue payments
   * No payment recovery tracking (difference between expected and actual payment)
   * No summary of payment delays by season
8. Rulebook Content Not Indexed
   * Images are extracted but not indexed or searchable
   * Rule sections have no metadata (difficulty, frequency in tests, etc.)
   * No way to find which rules are covered in the test pool

4. Feature Suggestions
🟢 Tier 1 — High Impact, Low Effort
1.1 — Bidirectional Rulebook-Question Links
* What it does: When viewing a question during a test, show "Related Rules" sidebar with links to jump to those rule sections in the PDF viewer. When viewing a rule, show "Questions about this rule" list.
* Why it matters: Referees studying for certification need to connect rules to test questions. Currently, rule references exist in the data but aren't exposed during study sessions.
* What it connects to: Rulebook viewer + Test questions + Rule references already parsed
* How to build it:
   * Add a new UI panel in the test question display showing rule references
   * Add a click handler that jumps to the rulebook page for that rule section
   * In the rulebook page, query the test dataset to find all questions referencing the current rule
   * Display as a list in a sidebar
* Effort estimate: Small (4–6 hours)
* Dependencies: Requires rulebook dataset loaded (already done)
________________


1.2 — Payment Alerts & Overdue Summary
* What it does: Add a "Payments Due" section to dashboard showing games where payment is overdue (today's date > paymentDate expected + 30 days) or missing. Color-code by severity.
* Why it matters: Referees need to track down late payments. Currently, payment tracking is just a Yes/No toggle with no visibility into delays.
* What it connects to: Game tracking + Dashboard
* How to build it:
   * Calculate expected payment date as date + 3 days (configurable)
   * Query games where (paid=No AND date + 3 days < today) OR (paid=Yes AND paymentDate empty)
   * Display count and list on dashboard; add a "Payment Recovery" button to filter games page
* Effort estimate: Small (3–4 hours)
* Dependencies: None
________________


1.3 — Improved Rulebook Search with Page Jumps
* What it does: When searching the rulebook, show results as a sortable list. Clicking a result jumps the PDF viewer to that page and highlights the match.
* Why it matters: Current search works but is disconnected from the PDF view—results don't help you navigate to the rule.
* What it connects to: Rulebook viewer + Search functionality
* How to build it:
   * Store page number with each rule section during parsing (already done: start_page, end_page)
   * When search completes, format results with page numbers
   * Add click handler to jump PDF to that page and scroll to highlighted text
* Effort estimate: Small (3–4 hours)
* Dependencies: PyMuPDF (already installed)
________________


1.4 — Rule Difficulty Tagging
* What it does: Automatically tag rules based on how frequently they appear in test questions. Display difficulty (Easy, Medium, Hard) in the rulebook sidebar.
* Why it matters: Referees studying should know which rules are tested more frequently—helps prioritize.
* What it connects to: Test questions + Rules
* How to build it:

* Effort estimate: Small (2–3 hours)
* Dependencies: Rule references already extracted

1.5 — Question of the Day (Complete)

5. Recommended Starting Point
Start with 1.1 (Bidirectional Rulebook-Question Links)
Why:
* Highest immediate user value: Referees studying are your primary use case. Connecting test questions to rules directly solves the #1 pain point (rulebook navigation + test isolation).
* Minimal effort: 4–6 hours, uses existing data structures, no schema changes, no new dependencies.
* Unlocks downstream work: Once question-rule linking is visible in the UI, it's natural to build on that (add difficulty tags, better search, etc.).
* Validates the architecture: This feature tests whether the refactored codebase is easy to extend—if it is, other features follow quickly.
* Low risk: It's purely additive; doesn't break existing features.
Implementation order (after 1.1):
1. 1.2 (Payment Alerts) — simple, high-value for users
2. 1.3 (Rulebook Search + Page Jumps) — improves core workflow
3. 2.1 (Game Analytics) — unlocks data-driven insights
4. 3.1 (Multi-user) — architectural prerequisite for future sharing/collaboration
